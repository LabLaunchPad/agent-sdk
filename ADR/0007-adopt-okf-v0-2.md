# ADR-0007 — Adopt OKF v0.2 for agent-facing knowledge

| Field      | Value |
| ---------- | ----- |
| Phase      | P1A   |
| Supersedes | —     |

## Context

Phase 0 built a bespoke compiled cache (`.context/`) with a hand-rolled
envelope — `source`, `sha256`, `generated_at`, a stored `freshness` enum —
specifically to keep AI agents from rediscovering the repository on every
task. ADR-0005 recorded that design and named its own residual risk plainly:
_"a cache summary can be fresh and still wrong… mitigated only by the
discipline of never citing `.context` as evidence — that is a discipline, not
a mechanism."_

Google Cloud's [Open Knowledge Format v0.2](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md)
(shipped 2026-07-25) is a vendor-neutral markdown-plus-YAML-frontmatter
standard for exactly this problem: knowledge meant to be authored by people,
generated by agents, and consumed by both. It was verified against its
primary source before this decision was made, not assumed from its name —
see the registry/spec evidence below.

Two findings drove the shape of this decision:

1. **OKF closes the ADR-0005 hole.** Its `verified: [{by, at}]` field, with
   trust tiers derived as `unverified` / `machine-confirmed` /
   `human-reviewed`, is the mechanism ADR-0005 said didn't exist. Freshness
   answers "has the source changed"; verification answers "was the summary
   ever correct." Phase 0 could only answer the first question.
2. **OKF has no content-hash staleness check.** `stale_after` is a calendar
   date — time-based decay, not change-based invalidation. Discarding the
   Phase 0 sha256 check in favour of it would be a silent regression, so it
   is kept as an extension field.

## Decision

Adopt OKF v0.2 for the four agent-facing knowledge surfaces: `.context/`,
`research/`, `specs/`, `ADR/`. Not adopted for `docs/` or directory
`README.md`/`TEMPLATE*.md` files — those are human/GitHub navigation and
templates, not knowledge concepts, and forcing them into the concept model
is scope creep beyond what the four surfaces above need.

### Envelope mapping

| Phase 0 field                     | OKF v0.2 field              | Note                                                    |
| --------------------------------- | --------------------------- | ------------------------------------------------------- |
| `source`                          | `sources[].resource`        | native                                                  |
| `generated_at`                    | `generated.at`              | native                                                  |
| —                                 | `generated.by`              | new, required within `generated`                        |
| `sha256`                          | `x_source_sha256`           | **extension** — OKF has no equivalent                   |
| `version`                         | `x_summary_version`         | OKF versions the bundle, not the summary                |
| `freshness: ACTIVE/STALE/INVALID` | derived                     | from hash match + `stale_after`, never stored           |
| `freshness: NOT_REQUIRED`         | `x_required: false`         | `status` is a different axis and must not be overloaded |
| `summary{}`                       | markdown body + frontmatter | OKF is markdown-first                                   |
| —                                 | `verified[]`                | new — closes the ADR-0005 gap, see ADR-0008             |
| —                                 | `status`, `stale_after`     | new                                                     |

### Extension-key policy

Fields prefixed `x_` are repository extensions, not part of OKF v0.2. OKF's
own conformance rule requires consumers to tolerate unknown keys, so this is
fully conformant. Extensions used: `x_source_sha256` (content-hash
staleness, absent from the spec), `x_required` (marks an entry deliberately
unmaintained; replaces the old `NOT_REQUIRED` freshness value since
`status` means something else in OKF), `x_summary_version`.

### Actor convention split

Two distinct `process:` actors are used, deliberately not conflated:

- `process:context-refresh` — mechanically compiled by `pnpm context:refresh`
  (deterministic, tool-generated, safe to regenerate anytime)
- `process:claude-code-session` — authored by an AI coding agent session
  (ADRs, specs; non-deterministic, LLM-authored, needs human review to reach
  `human-reviewed`)

This split lets a future trust-tier consumer distinguish "mechanically
derived, high confidence" from "LLM-authored, needs review" without either
being conflated into a generic `process:` bucket.

### Validator

A sixth validator, `okf-conformance-validator`, enforces the spec's own
conformance rule — parseable frontmatter, non-empty `type` — no more and no
less. It is deliberately as lenient as the spec requires: unknown `type`
values, unknown keys, and broken links must NOT be rejected, proven by
dedicated leniency fixtures in the adversarial test suite. `status`,
`stale_after`, `generated` and `verified` have OKF-defined shapes, so
malformed values in those specific fields ARE checked — that is a
correctness question, not a taxonomy one.

`context-staleness-validator` was rewritten to read the OKF envelope and
derive freshness/trust tier rather than trusting stored values (see
ADR-0008).

## Adversarial review

**Attack:** OKF v0.2 shipped six weeks after v0.1. Betting repository
infrastructure on a six-week-old spec risks another breaking revision before
this repository stabilizes.

**Failure modes:** OKF v0.3 changes or removes a field this repository
depends on; the spec's own governance stalls and drifts from what Google
Cloud actually ships in tooling; the extension-key convention (`x_`) turns
out to collide with a future official field name.

**Falsifying experiment:** re-query the SPEC.md at each phase boundary (same
discipline as ADR-0003's `TYPESCRIPT_7_REVISIT` gate). If a v0.3 changes a
field this repository extends or depends on, that specific field's migration
is scoped and executed before the next phase begins — not deferred
indefinitely.

## Alternatives considered

| Alternative                                                               | Why rejected                                                                                                                                                                                         |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Keep the Phase 0 bespoke envelope                                         | Forfeits the `verified`/trust-tier mechanism that closes ADR-0005's named residual risk, and every future consumer of this cache has to learn a repository-specific format instead of a portable one |
| Adopt OKF but drop the sha256 hash check in favour of `stale_after` alone | Silent regression — `stale_after` is time-based decay, not change-based invalidation, and cannot detect a source edited before its stale date                                                        |
| Apply OKF to the entire repository including `docs/` and READMEs          | `index.md` is reserved and would force renaming every existing `README.md`; no agent-facing benefit for pure navigation content                                                                      |

## Consequences

Easier: `.context/` cache summaries carry a standard, tool-recognizable
shape; a future consumer outside this repository (or a different AI coding
agent entirely) can read them without learning a bespoke schema; trust tiers
give a real mechanism for "has anyone actually checked this."

Harder: two conformance concerns now live in two validators
(`okf-conformance` for structure, `context-staleness` for freshness/trust)
instead of one — a deliberate separation of concerns, not accidental
complexity, but it does mean a single malformed record can produce two
related findings.

## Revisit trigger

A published OKF v0.3 that changes the shape of `sources`, `generated`,
`verified`, `status` or `stale_after`. Checked at each phase boundary,
alongside the `TYPESCRIPT_7_REVISIT` check.
