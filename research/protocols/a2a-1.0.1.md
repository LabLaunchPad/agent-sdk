## Governance and licensing [E4]

A2A (Agent2Agent) was originally announced by Google, then donated to the
**Linux Foundation**, which has governed the project since June 2025.[^a2a-lf-donation] It is maintained by a Technical Steering Committee
with representatives from AWS, Cisco, Google, IBM Research, Microsoft,
Salesforce, SAP, and ServiceNow — genuinely multi-vendor, not a
single-company project wearing an open-governance label.[^a2a-lf-governance]
As of the sources reviewed, 150+ organizations support the
protocol.[^a2a-lf-governance]

## Core concepts [E4]

Four primitives, confirmed via the protocol's own key-concepts
documentation:[^a2a-key-concepts]

- **Agent Card**: "a JSON document that serves as a digital business card
  for initial discovery and interaction setup" — identity, capabilities,
  endpoint URL, authentication requirements, and skills.
- **Task**: a stateful unit of work with a unique ID and defined lifecycle,
  supporting long-running operations and multi-turn interaction.
- **Message**: a single communication exchange, role-tagged (`user` or
  `agent`), carrying one or more Parts (text, files, structured data).
- **Artifact**: "a tangible output or a concrete result generated by a
  remote agent" — the deliverable, distinct from a Message's
  dialogue/instruction content.
- **`contextId`**: a server-generated identifier grouping multiple related
  Tasks across a series of interactions.

**Transport**: HTTP(S) with JSON-RPC 2.0 as the payload format for
requests/responses; Server-Sent Events (SSE) streaming for incremental
results, and server-initiated push notifications to a client-provided
webhook for long-running/disconnected scenarios.

**Trust model — the single most architecturally relevant fact**: remote
agents are explicitly documented as "opaque (black-box) systems, meaning
[their] internal workings, memory, or tools are not exposed" from the
client's perspective.[^a2a-key-concepts] This is a protocol-level design
decision, not an implementation gap — A2A does not attempt to share
internal agent state across the boundary it defines, unlike MCP's
tool-level integration model.
